# Architecture Decision Records

ADRs preserve hard-to-reverse or cross-cutting architectural decisions and their consequences.

- Use the next available four-digit identifier, for example `0002-use-outbox-for-events.md`.
- Create an ADR for durable architecture, persistence/data-model, security boundary, or external contract decisions;
  skip routine implementation choices.
- New ADRs start as `Proposed`. Set them to `Accepted` only after explicit user approval.
- Accepted ADRs are immutable. Supersede one with a new ADR that links to it.
- Use `TEMPLATE.md` and keep the decision technical and concise.

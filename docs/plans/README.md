# Plans

Plans record the scope, steps, acceptance checks, and recovery point for larger tasks.

- Create a plan when a task is expected to change more than three files.
- Use the next available four-digit identifier and a short kebab-case slug, for example `0002-task-export.md`.
- Draft the plan and exact file scope in chat first. Get approval to save it, then get approval for implementation
  before changing feature files.
- Keep the plan status current (`Proposed`, `In Progress`, `Blocked`, or `Complete`).
- Update `docs/memory/handoff.md` after each completed approved step and link the active plan there.
- Use `TEMPLATE.md`. Include relevant checks and tests in acceptance criteria.
